# ADR 0006 — shared inference, immutable PostgreSQL snapshots and review-only batch

Date: 7 November 2026. Status: implemented and verified on Ubuntu ARM64 with Docker Engine; production approval remains pending.

Use one `booking_frame` input contract and the existing `build_features` implementation for online and batch inference. Persist the training agent vocabulary and column order with the model; LightGBM aligns categorical levels to its learned metadata. Preserve baseline handling of missing children, agent/company codes and ADR. Reject labels, nationality, post-booking columns, non-finite values and inconsistent date forms at the serving boundary. Derive booked date from arrival and lead time; do not accept caller-supplied booked dates.

Use an explicit exported model/policy pair with SHA-256 fingerprints, not an implicit “latest” model. Load only trusted local joblib artifacts; hashes detect accidental mismatch but do not authenticate a hostile manifest. The health endpoint reports readiness and the diagnostic per-hotel gate. It is not a quality-gate approval. Booking predictions cover booking-to-arrival, not the seven-day decision horizon.

The student has authorised creating a project-owned PostgreSQL snapshot from the provided dataset. Store an immutable, content-addressed JSONB payload in `hotel_snapshots`. A payload includes target live bookings, inferred blocks and matured nightly aggregate history. Source row IDs preserve exact duplicate bookings; they are not genuine PMS reservation IDs. No future target labels or reservation status fields enter booking payloads. Queries bind parameters; insertion is transactional and idempotent. The batch requires an explicit snapshot ID and matching model/policy hashes. A JSON file supports replay and parity checks; it is not a substitute for the required tested PostgreSQL path.

The current retrospective export still cannot establish event-time feature values. Historical release counts exclude statuses dated on/after the current decision day. Calibration must have matured before the decision, and the batch demands a complete mature recalibration window. Final-state data, unknown capacity, multi-night inventory and inferred groups retain the limitations documented in Stages 4 and 5.

Use the unchanged C2 reference policies for this service demonstration, clearly labelled in the manifest. Stage 5 candidates remain unsigned and are not promoted. Batch outputs a candidate quantity and walking-risk/cost context but authorises zero oversell and requires human approval. Resort's diagnostic calibration failure remains visible.

Use Python's standard-library HTTP server for a small local/coursework demonstration, binding localhost by default and serialising model calls. This avoids a new web-framework dependency and gives a compact JSON interface. It is not a hardened public application server: production authentication, TLS, bounded concurrency and gateway limits remain deployment work. Do not expose it to the public network. Payload size and per-socket timeouts are bounded; payloads and database credentials are not logged.

The image uses a slim Python base, pinned inference dependencies, a non-root user and external read-only model artifacts. Compose restricts published ports to localhost and supports a read-only API root filesystem. Dataset, notebook, virtual environment and secrets are excluded from the build context. Raw snapshot generation runs on the full host environment; the inference image only consumes already exported snapshots/artifacts. Image build, runtime compatibility and image size were established with `scripts/container_smoke.py`, and PostgreSQL/parity/tests with `scripts/verify_stage6_containers.py --tests`.

## Course-notes verification update

The supplied Session 3 notes specify Docker Engine on Linux, and the VM guide requires ARM64 Ubuntu on Apple Silicon. The existing Ubuntu 26.04.1 VM was used rather than installing Docker Desktop. The image, HTTP endpoint, batch, clean SIGTERM shutdown and PostgreSQL 18.1 Compose path all passed; 93 Linux tests passed with no skips. PyArrow had to be retained in the inference pins because the saved pandas metadata requires it during model deserialization. Cross-platform floats use a documented 1e-12 tolerance, with exact discrete policy/quantity checks. See the Stage 6 report for measurements and evidence.
